## Why

See ADR-0003. Goal: the same picture as today with less CPU, no skirts or LOD pops, per-node culling, terrain to the edge of the world without the far skin, and a GPU height texture that G2.1 grass will sample.

## Ground rules

- CPU height data (`src/world/heightField.ts`, `terrainData.ts`) stays the authority; the textures are derived copies built once at load.
- Module layers (`scripts/audit.mjs`): pure code in `src/world` (selection, texture packing), rendering in `src/render`, wiring in `src/app`. Files ≤ 350 lines; `@hot` / `@amortized` tags on per-frame and occasional functions; no allocation in `@hot` paths.
- Keep the existing chunk path working behind `?terrain=chunks` (default becomes `cdlod`). Do not delete chunk code, the worker or their tests in this step.
- Do not change tests' assertions or audit thresholds. The spike benchmark (`spike/`) keeps its own chunk scene untouched.
- Both backends: WebGPU and the WebGL2 fallback (headless audit runs WebGL2). Use `textureLoad` (texel fetch) in the vertex shader, never filtered sampling of float textures in the vertex stage (`float32-filterable` is optional).

## Phase A — textures (pure packing in `src/world/terrainTextures.ts`, upload in `src/render/terrainTextures.ts`)

1. **Height texture**: 2048 × 2048 `R32F` (`FloatType`, `RedFormat`), texel (i, j) = height in metres of lattice point i, j of the 2 m grid (`dequantize(sampleQuantized(...))`), origin at `WORLD_MIN`. `NearestFilter`, no mipmaps, `ClampToEdgeWrapping`. Lattice has 2049 points per side: store 2048 and clamp the last row/column (document it), or use 2049 if three accepts non-power-of-two (it does on WebGPU and WebGL2; prefer 2049 for exactness).
2. **Material texture**: same lattice, `RGBA8` (`UnsignedByteType`), R = sand, G = rock, B = earth, A = baked horizon AO — exactly the values the chunk path writes into its vertex colours (`classifyTerrain`, `terrainAo`). Linear filtering, mipmaps on (fragment sampling). Low tier: build at 4 m (1025²) to save memory.
3. Build both in the terrain worker after it installs the tiles (it already has the data); transfer the buffers. Measure and report build time (worker `performance.now()`); target < 1.5 s on desktop. If AO for the whole world is slower, compute AO at 4 m and upsample, and say so.
4. Account bytes in `MemoryPartition.Gpu`; count both uploads in the upload-rate counter.
5. Unit tests: packing matches `heightAt` at lattice points (exact) and `classifyTerrain` at sample points; dimensions and edge handling.

## Phase B — node selection (`src/world/cdlod.ts`, pure)

Strugar's CDLOD, adapted:

- Quadtree over the world square: root = 4096 m; leaf = 64 m nodes (LOD 0). Levels L = 0..6 (64 m … 4096 m). Every node is drawn with the **same** grid patch of `PATCH = 32` quads per side (so LOD 0 = 2 m spacing = the data resolution; LOD L spacing = 2·2^L m).
- Distance ranges: `range[0] = lod0Distance` from the tier (low 110, med 150, high 200 m); `range[L] = range[L-1] · 2`. A node at level L is selected when the camera-to-node-AABB distance (3D, using node min/max height) is within `range[L]`; it subdivides when its children's range covers it (standard CDLOD `LODSelect`). The top level covers the whole world: terrain reaches the edge of the 4 km square at every tier.
- Morph: each level morphs to its parent over the last 30 % of its range: `morphStart[L] = range[L-1] + 0.7 · (range[L] - range[L-1])` (L ≥ 1; for L = 0 use `0.7 · range[0]`), `morphEnd[L] = range[L]`.
- Node min/max height: precompute a min/max pyramid from the height data once (pure function; 64 m leaves → root).
- Frustum culling: test each node's AABB against the camera frustum planes (pass planes in as a `Float32Array(24)`; the pure module must not import three). Culled nodes are skipped (but still subdivided correctly — culling only removes output).
- Output into preallocated arrays: per selected node `(originX, originZ, size, level)` in a `Float32Array`, count per level. Allocation-free after construction. `@hot`.
- Shadow casters: select a second list for the shadow cascades: no frustum culling against the camera, but limited to the tier's shadow `maxFar` around the camera (nodes beyond do not cast; they still receive).
- Unit tests (synthetic flat and sloped height pyramids): selected nodes tile the covered area with no overlap and no gap; levels of neighbours differ by ≤ 1; morph ranges are monotonic and inside each level's range; node count at each tier for a camera at the village ≤ 400; culling removes nodes behind the camera only.

## Phase C — rendering (`src/render/cdlodTerrain.ts`)

- One shared `BufferGeometry` grid patch: (PATCH+1)² vertices in [0,1]², 16-bit indices. Instancing: one `InstancedMesh`-style draw per level with an instance attribute `vec4(originX, originZ, size, level)` (or one draw for all levels; your choice — report draws per frame). Instance buffers preallocated to the maximum node count; update only the used range when the selection changes (compare to the previous selection; selection at most every frame, typically cheap).
- Camera-relative positions as today (the app moves `root` by −camera; pass the eye offset as a uniform so world xz for texture lookups is exact — keep f32 precision as the chunk path does).
- Vertex shader (TSL `positionNode`):
  1. `gridPos = origin + uv · size` (world xz).
  2. Morph factor `k = clamp((dist(eye, gridPos3D) − morphStart[level]) / (morphEnd − morphStart), 0, 1)` with dist using the height at gridPos (one load) — standard CDLOD: `morphed = gridPos − fract(uv · PATCH / 2) · (2 / PATCH) · size · k` (snap odd vertices toward the even ones).
  3. Height at the morphed position: the morphed xz lies on the lattice of the level or halfway between two lattice points of the parent; fetch the two endpoint texels (`textureLoad`) and lerp. Clamp texel indices to the texture.
  4. Normal: central differences on the height texture at the vertex's own spacing (4 loads, at the morphed position's lattice), passed as a varying. (Cheaper alternative if profiling says so: a precomputed RG8 normal texture; not required.)
  5. Material weights: pass world xz as a varying; the fragment samples the material texture (one filtered sample) instead of the vertex colour attribute.
- `terrainMaterial.ts`: add a mode that reads weights/AO from the material texture at world xz and the geometric normal from the varying; everything else (noise texture, triplanar, lite) unchanged. Keep the attribute mode for `?terrain=chunks`.
- Shadows: the terrain casts with the caster selection (Phase B) and receives everywhere. Use a separate instanced mesh for casters with `castShadow = true` and `receiveShadow = false` drawn only into shadow passes if three allows it (e.g. a material with `colorWrite = false` that is layered for shadows only); if three cannot restrict a mesh to shadow passes, cast from the main mesh and report the shadow triangles.
- Far-terrain skin (`farTerrain.ts`): not needed in CDLOD mode (the root node covers the world); keep it for `?terrain=chunks`. The ocean's floor texture and coast map are untouched.
- Telemetry (Phase E fields): in CDLOD mode `residentChunks` → report `world.terrainMode`, `world.nodes { selected, culled, perLevel[] }`, `world.shadowCasterNodes`, triangles per pass computed from node counts × patch triangles. HUD line 1 shows `nodes 212 · cull 140 · L0 18` instead of chunk counts. `chunkBuildMs` and `workerQueue` show n/a in CDLOD mode. Add `world.terrainTexturesMs` (worker build time).
