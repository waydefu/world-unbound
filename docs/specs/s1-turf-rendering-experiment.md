# 全域草毯繪製實驗

2026-11-21，使用者同意「可，開始實驗，開完pr跟我說我合了跑看看」。依照[全域草毯驗收標準](s1-rooted-soil.md#全域草毯驗收)比較相同世界根位、鏡頭與光照。畫面與手機效能各自待驗收。

以 #42 的 10–13 m 原模淡出為對照。兩個試驗沿用 79,524 葉／m² 的根位分布與完整母版。近處維持 19 頂點和 22 個三角形。進入次像素區時，以固定的草簇種子和螢幕投影尺度分派至簡化葉形，保留折線、根、尖端及來源葉色。同一草簇只會分派至一種網格。

- `turfTrial=mesh` 保留原模對照的實例數和 10–13 m 衰減帶，量測改用簡化葉形的差異。
- `turfTrial=canopy` 在次像素區由母版烘出的三層投影面積、葉色及立體草片共同提供覆蓋。簡化葉片取草簇序列的等面積前綴，全部根位仍可在玩家靠近時呈現。視野內接手的草層共用現有風場、地形及植被遮罩。
- 使用 `?sward=world&turfLod=30&cam=6&turfSite=lowland&turfView=standing&q=med&scale=1`。移除 `turfTrial` 回到對照。加上 `turfStats=1` 診斷各級提交量，正式幀間隔測試時移除診斷。
- WebGPU 間接繪製和 WebGL2 實例繪製共用根位和門檻。分開量手機 WebGPU、WebGL2 幀間隔，鎖定比率 1.0，記錄 60 秒及至少 10 分鐘熱機。以河谷、坡地、高地及接縫檢查貼地、站姿、抬升、轉向和移動。核對厚度、葉色、薄葉輪廓、是否閃爍及遠景是否失去草毯覆蓋。

實驗透過 URL 啟用。真機與畫面都達標後才討論預設設定。

### 接手順序與決策

1. **建立可比較的基線。** 先在實驗分支固定上述入口，記下 commit、實際後端、繪製尺寸與暖機條件。用同一初始風相位先錄固定站姿，再用相同移動路線錄轉身與跨區塊。兩種路徑分開比較。每組暖機後記錄 60 秒，交替重跑全開對照以察覺溫度漂移。另開一次 `turfStats=1` 取得完整葉與簡化葉各自的提交量及樣本年齡，正式幀時間測試關閉讀回。
2. **先做單層成本對照。** 下一支實驗 PR 要補上僅供診斷的獨立開關。全開為對照，每次只停一項，依序測試立體草片、完整葉、簡化葉、地表三層草冠。葉片與草片先只停繪製，維持選取、重建及其他層的權重；地表改用保留同一植被遮罩與底色的廉價材質變體，略過草冠取樣。任何開關均不得觸發自動補償或改變風、光、解析度與其他 LOD。每組保存同鏡頭截圖、JSON、幀間隔 p50／p95／p99、超過 50 ms 的幀數及 GPU 通道加總。單層開關量到的是該組合的邊際成本，各差值不能相加當作逐層 GPU 時間。
3. **用實驗決定改哪裡。** 優先驗證半透明立體草片的重疊繪製。若停繪草片能重複改善幀間隔，且站姿輪廓變化小，再試減少相同畫素的重疊、保留斜視草尖。若完整葉、簡化葉或地表草冠影響更大，就先處理量到的那一層。若慢幀集中在移動，再逐幀記錄選取、重建、上傳與幀間隔，分辨 CPU 尖峰和持續繪製成本。所有停繪畫面只供歸因。
4. **放行條件。** 優化候選須恢復完整場景。畫面以 A 河谷、D 坡地、F 高地、I 接縫的貼地草量、葉色、交錯與接地感為下限，補站姿與抬升，錄下轉身、走動、跨區塊及風勢。特別檢查 2–10 m 的草尖、遮蔽與厚度，並用同鏡頭核對使用者要求的 10 m 後原模逐漸交棒。出現密草圈、平綠遠坡、密度跳變或閃爍即保留在試驗。手機 Medium 鎖 1.0 分別驗證 WebGPU／WebGL2；WebGPU 以暖機後 60 秒穩定 60 FPS、零幀超過 50 ms 為短測目標，再做至少 10 分鐘熱機。將畫面、幀間隔、實際後端與熱機結果分開記錄，交使用者驗收後才切預設。
