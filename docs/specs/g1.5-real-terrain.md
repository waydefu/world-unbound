## Goal

Replace the procedural terrain with the real bare-earth terrain of Hellesylt, Norway (fjord head, 0–1029 m), baked at build time into committed, licensed, verifiable height tiles. The runtime keeps its contracts (quantised integer lattice at 2 m, chunk streaming, render = collision). Seabed below the fjord is procedural. Lighting moves to the site's latitude.

## Phase A — bake pipeline and data (`scripts/terrain/`, `assets/`)

### A1. Quantisation (world core)

`src/world/constants.ts`: `HEIGHT_QUANTUM = 0.02`, new `HEIGHT_OFFSET = 600` (metres), `TERRAIN_VERSION = 2`. Stored value `q` (Int16) ↔ height `q * HEIGHT_QUANTUM + HEIGHT_OFFSET` (range −55.36 … 1255.34 m). Update every dequantisation site (`heightField.ts`, `terrainMesh.ts`, AO, sea floor — grep for `HEIGHT_QUANTUM`) through one helper `dequantize(q)` / `quantize(h)` in `heightField.ts`.

### A2. Bake script — `scripts/terrain/bake-hellesylt.mjs` (Node ≥ 22, no new dependencies)

1. Convert the centre to EPSG:25832 (transverse Mercator, central meridian 9° E, k0 0.9996, false easting 500000; WGS84 ≈ ETRS89 here) and snap it to an even metre. The baked square is 4096 m × 4096 m centred there.
2. Download it at 2 m as 2048 × 2048 **lattice-point** samples (sample i at `x0 + 2i`; request the bbox `[x0 − 1, y0 − 1, x0 + 4095, y0 + 4095]` with `size=2048,2048` so pixel centres fall on lattice points) as four 1024 × 1024 requests (2048 m each), retrying each up to 3 times. Save nothing raw into the repo.
3. Sea and seabed: cells with value ≤ 0.05 that are 4-connected to a cell with value exactly 0 are water. Compute the Euclidean distance `d` (m) from each water cell to the nearest land cell (two-pass chamfer or exact EDT). Seabed height = `−min(55, 1.0 + 0.55 · d)` (fjord walls continue steeply under water). Leave land as measured.
4. Orientation: game +x = east, +z = **south**. Row j of the output is z = −2048 + 2j (north first), column i is x = −2048 + 2i. Game origin (0, 0) = the snapped centre.
5. Quantise with A1 into Int16. Split into 16 tiles of 512 × 512 samples (1024 m). For each tile: row-wise delta encoding (first sample raw, then differences, as Int16 with wrap), then `zlib.deflateRawSync(level 9)`. Write `assets/terrain/hellesylt/t_<col>_<row>.bin` (col, row 0..3 from the north-west). Each file must be ≤ 2 MiB; fail the bake if not.
6. Write `assets/manifests/terrain-hellesylt.json`: global fields (source product, service URL, CRS, centre lat/lon and snapped UTM, bbox, sample spacing, retrieval date, licence `CC-BY-4.0`, attribution `© Kartverket`, statement `Modified: resampled to 2 m, quantised to 2 cm, seabed synthesised`, `pipeline_version: "terrain-bake/1"`, quantum, offset) and per tile `path, sha256, origin, license, encoding ("int16-le row-delta, deflate-raw"), pipeline_version, bytes`.
7. Print min/max height, water %, and the max tile size.

Run it once; commit the 16 tiles and the manifest (they are the authority from now on). Do not wire it into `npm run build` or CI.

### A3. Loader (pure decode in the world core)

`src/world/terrainData.ts`:
- `decodeTile(bytes: Uint8Array): Int16Array` — inverse of A2.5 *after* inflation (inflation happens in the caller; see below).
- `installTerrain(tiles: Int16Array[])` — assembles a module-level `Int16Array(2048 * 2048)`.
- `terrainInstalled(): boolean`.
- `sampleQuantized(ix, iz)` (moved/updated in `heightField.ts`) reads it: lattice `ix, iz` ↔ column `ix + 1024`, row `iz + 1024`; outside the square return `quantize(−55)` (open deep water). If nothing is installed, throw a clear error (never silently fall back to procedural heights).
- Inflation: `src/app/terrainAssets.ts` (browser) fetches the 16 files (URLs via `import url from '…/t_0_0.bin?url'` or `new URL(…, import.meta.url)` — no root-absolute paths) and inflates with `DecompressionStream('deflate-raw')`. Verify each file's sha256 against the manifest with `crypto.subtle.digest` and refuse to start on mismatch (show the boot error). Tests inflate with `node:zlib` in a vitest setup file (`tests/setup/terrain.ts`, registered in `vite.config.ts` `test.setupFiles`).
- The terrain worker loads the tiles itself at start (same module), then answers jobs; the main thread loads them before `setCamera`. Report the load time in telemetry (`world.terrainLoadMs`).
