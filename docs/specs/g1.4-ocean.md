## Goal

Replace the flat sea plane with an ocean that reads as water from the six test cameras: moving Gerstner swell, multi-band normal detail, Fresnel reflection of the physical sky, a sun glint, depth-dependent colour and shoreline foam. Add main-app GPU timing so effect costs can be measured on the phone. Mobile budget for the ocean: ≤ 1.5 ms GPU at 2.2 MP. No texture assets.

Out of scope: screen-space reflections, refraction of the terrain through the water, shadows on water, boats/buoyancy, reflections on terrain (wet ground stays as is; noted follow-up).

## Background you need

- Today `src/render/environment.ts` owns `sea` (a 9 km `PlaneGeometry`, `MeshStandardNodeMaterial`, transparent 0.86) and `App.placeWorld()` sets `environment.sea.position.set(0, -eye.y, 0)`. The camera is at the origin; absolute world xz = local xz + eye xz.
- `src/render/sky.ts` (`SkyDome`) samples the sky-view table (`table`, `radianceScale`, `sunDir`, `overcast`, `overcastZenith`, `exposure` uniforms) and returns pre-exposed radiance. The ocean must reflect exactly this sky.
- World: 32×32 chunks of 64 m (`WORLD_MIN`..`WORLD_MAX` = −1024..1024 m), sea level 0, `heightAt(x, z)` in `src/world/heightField.ts`. Outside the world the sea is deep.
- Pre-exposure: everything the ocean emits must be multiplied by the same exposure uniform the sky uses.
- Layers (enforced by `scripts/audit.mjs`): pure code in `src/world` / `src/env`, three.js in `src/render`, wiring in `src/app`.

## Phase A — pure data (`src/world`, `src/env`)

### A1. Sea-floor height map — `src/world/seaFloor.ts`

```ts
export const SEAFLOOR_RES = 4;                                   // metres per texel
export const SEAFLOOR_DIM = (WORLD_MAX - WORLD_MIN) / SEAFLOOR_RES; // 512
/** Heights in metres (ground or seabed) at texel centres, row-major, z rows. */
export function buildSeaFloor(out: Float32Array): Float32Array
```

Texel (i, j) centre = (`WORLD_MIN + (i + 0.5) * RES`, `WORLD_MIN + (j + 0.5) * RES`); value = `heightAt(x, z)`. Clamp nothing.

Build it in the terrain worker so the main thread never pays for 262 k samples:
- `src/app/terrainWorker.ts`: if the message is `{ kind: 'seafloor' }`, build into a new `Float32Array(SEAFLOOR_DIM²)` and post `{ kind: 'seafloor', heights }` with the buffer transferred; otherwise behave as today.
- `src/app/terrainClient.ts`: add `requestSeaFloor(): Promise<Float32Array>`. With a worker, post the message and resolve on the matching reply (the existing `onmessage` must route `kind === 'seafloor'` to the promise and everything else to `results`). In main-thread fallback mode, resolve with `buildSeaFloor` directly.
- `TerrainRequest`/`TerrainResult` must not change shape.

### A2. Wave set — `src/env/ocean.ts`

```ts
export interface Wave { dirX: number; dirZ: number; wavelength: number; amplitude: number; steepness: number; speed: number }
/** Four deterministic Gerstner waves for a weather state (deep-water dispersion). */
export function waveSet(weather: Weather): readonly Wave[]
```

- Base direction: waves travel towards the shore, i.e. towards +z (south). Spread the four directions at −35°, −10°, +15°, +40° around +z.
- Wavelengths 42, 23, 13, 7.5 m. Speed from deep-water dispersion: `speed = sqrt(9.81 * wavelength / (2π))`.
- Amplitude = `wavelength * slope / (2π)` with slope per weather: clear 0.035, cloudy 0.05, rain 0.07, storm 0.11 (same for all four).
- Steepness `Q_i` such that `Σ Q_i · k_i · A_i ≤ 0.8` (no looping crests): set each `Q_i = 0.8 / (4 · k_i · A_i)` capped at 1, with `k_i = 2π / wavelength`.
- Return precomputed constant arrays per weather (no allocation per call).

### A3. Tests — `tests/ocean.test.ts`

- `waveSet`: four waves per weather; every direction unit length; `Σ Q·k·A ≤ 0.8 + 1e-9`; storm amplitudes > clear amplitudes; speeds match dispersion within 1e-9; calling twice returns the same array instance.
- `buildSeaFloor`: length `SEAFLOOR_DIM²`; deterministic; 20 random texels equal `heightAt` at their centres within 1e-6; a texel north of the coastline (far −z, deep water) is < −2 m and the town centre texel is > 2 m.

Run the phase checks; commit `feat(g1.4): sea-floor height map and deterministic wave set`.

## Phase B — ocean rendering (`src/render`)

### B1. Share the sky — `src/render/sky.ts`

Add a public method `radiance(dir: Node): Node` that returns the **pre-exposed** sky radiance for a world-space direction (vec3), built from the same uniforms and the same table lookup as the dome, *without* the sun disc, moon disc and stars, and with the direction's y clamped to ≥ 0.01 (reflections never look below the horizon). Refactor the dome's own shader to call the same internal TSL function so the two cannot drift. Also expose read-only accessors for the `sunDir` uniform and a new `sunRadiance` uniform (vec3: sun disc radiance before the disc clamp, i.e. `π · T · sunVisibility / 6.8e-5`, then × exposure in the shader) — the ocean uses them for the glint.

### B2. Ocean mesh — `src/render/ocean.ts` (new)

Export `class Ocean` with `mesh`, `setSeaFloor(heights: Float32Array)`, `setWeather(weather)`, `update(eyeX, eyeY, eyeZ, timeSeconds)` (`@hot`), and dispose-free (lives as long as the app).

Geometry — camera-centred grid, built once:
- A square grid of 160 × 160 quads whose spacing grows geometrically from 1.5 m at the centre to ~80 m at the edge, covering ±3500 m: vertex coordinate along each axis `s(t) = sign(t) · 1.5 · (pow(r, |t|) − 1) / (r − 1)` for integer `t` in [−80, 80], with `r` chosen so `s(80) ≈ 3500` (solve once with a few Newton or bisection steps at construction). Positions in metres, y = 0. Indexed `BufferGeometry`, `frustumCulled = false`.
- Each frame `update` places the mesh at `(−(eyeX mod 1.5), −eyeY, −(eyeZ mod 1.5))` (snap to the finest spacing so near vertices do not slide over the waves) and stores the eye offset in a uniform so the shader can form absolute world xz = `positionLocal.xz + snappedEye.xz` where `snappedEye = eye − (eye mod 1.5)`.

Material — `MeshBasicNodeMaterial({ transparent: false, fog: true, side: FrontSide })`, `name = 'ocean'`, `renderOrder = 1`. All lighting is done in the shader:

Vertex (`positionNode`):
- world xz `p`; for each of the 4 waves (uniform arrays or 4 separate uniforms, set by `setWeather`): phase `θ = k (d · p) − ω t` with `ω = k · speed`; Gerstner displacement `x += Q A d.x cos θ`, `z += Q A d.z cos θ`, `y += A sin θ`.
- Attenuate the displacement by water depth so waves die on the beach: `depthFade = smoothstep(0.3, 4, depth)` where `depth = −seaFloorHeight(p)` (see sampling below), and by distance: `smoothstep(2500, 900, length(positionLocal.xz))`.
- Pass the analytic Gerstner normal (sum of the standard Gerstner normal terms) to the fragment stage as a varying.

Sea-floor sampling (both stages): a `DataTexture(heights, 512, 512, RedFormat, FloatType)`, `LinearFilter` (if float-filterable is not guaranteed on WebGL2, use `NearestFilter` plus manual bilinear, or upload as `HalfFloatType` with `DataUtils.toHalfFloat` — pick one and record why), clamp-to-edge; uv = `(p − WORLD_MIN) / (WORLD_MAX − WORLD_MIN)`; outside [0,1] treat as −40 m (deep). Until `setSeaFloor` is called, a 1×1 texture of −40.

Fragment (`colorNode`, returns pre-exposed radiance):
1. Normal: Gerstner normal + detail from two bands of scrolling noise at world xz: `n1 = mx_noise_float(vec3(p * 0.23 + t * (0.05, 0.03), t * 0.1))`, `n2` at 0.9 /m and opposite drift; perturb by finite differences as in `terrainMaterial.ts` (E = 0.08), strength `0.35 · (slope/0.035)` capped at 1, faded by `smoothstep(400, 60, dist)`. Normalise.
2. View vector `V = normalize(−positionWorld)` (camera at the origin). `R = reflect(−V, N)`, force `R.y ≥ 0.01`.
3. Fresnel (Schlick, water F0 = 0.02): `F = 0.02 + 0.98 · (1 − max(dot(N, V), 0))^5`.
4. Reflection: `sky.radiance(R)`.
5. Sun glint: `glint = sunRadiance · exposure · pow(max(dot(R, sunDir), 0), 900) · 4 · F` (sharp normalised lobe; tune the exponent so the dusk camera shows a glitter path, not a solid bar).
6. Water body colour (scattered light from below): deep `(0.004, 0.016, 0.022)`, shallow `(0.02, 0.09, 0.085)`, mixed by `exp(−depth / 6)`; multiply by the sky irradiance proxy `sky.radiance(vec3(0,1,0))` × 0.6 so it darkens at night with the sky.
7. Shore foam: `foam = smoothstep(1.2, 0, depth) · (0.5 + 0.5 · n1)` plus crest foam `smoothstep(0.8, 1, waveY / Σamplitude)` × 0.4 (only rain/storm: multiply by `max(0, slope − 0.05) / 0.06` capped at 1); foam albedo 0.8 lit by `sky.radiance(vec3(0,1,0))` + sun term `sunRadiance · max(sunDir.y, 0) · 6.8e-5` (i.e. back to illuminance) — keep it simple and record what you did.
8. Output `mix(body, reflection, F) + glint`, then `mix(…, foamColour, foam)`. Clamp to ≤ 60000.

## Phase C — GPU timing in the app

- `src/render/renderer.ts`: pass `trackTimestamp: true` to `WebGPURenderer` only when the adapter has `timestamp-query` (it is harmless otherwise, but keep it explicit).
- `src/app/gpuTimer.ts` (new): mirrors `spike/threeRunner.ts`: after each `render`, if no resolve is pending, call `renderer.resolveTimestampsAsync('render')` and push the result (ms) into a ring buffer of the last 240 samples. Expose `p50`, `p95` (reuse `src/perf/frameStats.ts` percentile helpers if they fit; otherwise a small sort of a scratch copy at low frequency only). three keeps one timestamp per render context and overwrites it each frame, so each resolve is the latest frame's GPU time, not a sum (see the comment in `spike/threeRunner.ts`).
- Telemetry: `report.ts` `frames` section gets `gpuP50Ms`, `gpuP95Ms`, `gpuSamples` (null on WebGL2 / no feature); HUD shows `gpu p50/p95` on the frame line. Note in a comment that mobile GPUs down-clock when lightly loaded, so absolute values are inflated; compare A/B runs only.
- Test: if you add pure percentile code in `src/perf`, unit-test it.

## Phase D — far terrain and daylight water body (added after review)

Review of the Phase B screenshots found a regression at the default camera (cam 5): where terrain chunks are not streamed (beyond the LOD view radius) the ocean now discards over land, so the sky shows through as a pale slab. Before G1.4 the flat sea hid it.

### D1. Far terrain — `src/render/farTerrain.ts` (new)

- One `Mesh` covering the whole world (`WORLD_MIN`..`WORLD_MAX`), a 256 × 256 quad grid (8 m spacing), built once, `frustumCulled = false`, added under the terrain root (`TerrainChunks.root`) so it moves with the world, **not** inside the bundle group.
- Vertex heights come from the sea-floor height texture (share the `DataTexture` the ocean already owns; expose it from `Ocean`). Until it arrives, place the mesh 50 m below sea level (invisible under the ocean).
- Lower each vertex by `0.6 + 0.004 · (distance from the camera, m)` so streamed chunks always win the depth test where both exist (no z-fighting), and the far skin never pokes through near terrain. Also set `material.polygonOffset = true`, `polygonOffsetFactor = 1`, `polygonOffsetUnits = 1`.
- Material: reuse the G1.3 terrain look cheaply — a `MeshStandardNodeMaterial` with the same macro grass colour, sand below 2.4 m, seabed tint below 0 m, roughness 0.9, no micro-relief, no AO (it is only seen far away). Absolute world position via the same eye-offset uniform pattern as `terrainMaterial.ts`.
- Casts no shadow; receives shadows.
- Visible in all tiers.

### D2. Daylight water body

In the ocean fragment shader, light the body colour with sky + sun instead of sky zenith × 0.6: `bodyLight = sky.radiance(up) · π · 0.5 + sunRadiance · 6.8e-5 · max(sunDir.y, 0)` (both pre-exposed), times the body colour. Check that midday cam 0/5 water is a plausible blue-green, not near-black, and dusk cam 3 is unchanged in character.

### D3. Checks

Phase checks, visual audit, regenerate `artifacts/visual/g1.4-sheet.png` and `g1.4-cam5.png` (cam 5, default settings). The pale slab must be gone: far land shows as terrain-coloured ground fading into fog. Commit `fix(g1.4): far-terrain skin under unstreamed land; sky-and-sun lit water body`.
