# 機械鳥無人機與啟動演出研究

狀態：研究提案，日期：2026-11-18。本文整理 WORLD UNBOUND 的機械鳥造型、自由飛行、啟動演出與驗收方式。時間、羽板數量與效能門檻都是待驗證的原型起點。

## 1. 純程式生成機械鳥

以 TypeScript 生成有厚度、倒角和可用法線的 3D 網格。參考圖的特徵是尖喙、窄機身、藍黑金屬刀片翼、細金邊、扇形尾翼與紫色光羽。玩家主要從後上方看鳥，因此優先建立背部稜線、翼尖的扇狀間隙和從背後仍可辨認的尾翼。

| 部位 | 幾何與動作 |
| --- | --- |
| 頭部與機身 | 沿脊線由尖喙、胸腔到尾根配置截面，將截面接成分片裝甲，肩部保留關節和傳動桿的活動空間。 |
| 主翼 | 每側設肩、肘、腕三段。內翼疊短羽板，外翼先試 7–9 片長羽刀。以曲線定義羽刀輪廓，擠出厚度和倒角，每片可獨立調整長度、後掠、扭轉與張角。 |
| 尾翼 | 先試 4–5 片扇形尾板，獨立控制展開、俯仰與偏轉。 |
| 紫色光羽 | 以貼著翼緣的薄網格配合 TSL 生成點陣和亮邊。高速才放出短翼尖拖尾，滑翔時保留清楚的金屬剪影。 |

材質沿用現有日月光與曝光，研究從天空場取低頻反射，讓倒角在轉身時依序接住亮光。首輪先用灰模看剪影及關節活動，再做金屬、反射與紫光。初始化時生成幾何並準備材質，重複羽板可按幾何與材質實例化，飛行中更新姿態與實例矩陣。手機依螢幕佔比削減輝光、拖尾與細部羽板，優先保留輪廓與關節動作。

## 2. 操控與飛行鏡頭

預設採第三人稱追尾。鏡頭位在鳥背後上方，視線稍微前瞻，翻滾幅度低於機體。鳥身明顯側傾時，玩家仍能用地平線辨認方向。第一人稱可沿用同一套飛行狀態，將鏡頭設在鳥頭附近並加上穩定處理。

| 動作 | 翼面表現 |
| --- | --- |
| 滑翔 | 主翼展平，外羽和尾翼小幅修正。 |
| 拍翼爬升 | 肩、肘、腕依序帶動，翼尖稍晚跟上。下拍展羽，上拍略收。 |
| 側傾轉彎 | 內側翼稍收，外側翼維持伸展，尾翼跟隨偏轉。 |
| 俯衝與拉起 | 俯衝時雙翼往後收。拉起減速時逐步展翼並開尾。 |

建議以固定時間步更新世界座標的飛行狀態，讓姿態與鏡頭讀取同一份飛行資料。地形淨空沿用權威高度查詢，海面另取世界海面高度。渲染時使用鳥的世界位置減去鏡頭位置，與現有相機相對座標一致。飛行鏡頭獨立於六個固定驗收鏡頭，讓原有場景驗收仍能重現。動態鳥體留在靜態地形渲染批組之外。採用現有 TypeScript、three.js、TSL 及 WebGPU／WebGL2 Lite 路線。 [架構](../architecture/README.md) · [架構決策](../adr/0002-target-architecture.md) · [相機與渲染迴圈](../../src/app/App.ts) · [權威地形高度](../../src/world/heightField.ts)

## 3. 按鈕、讀取演出與聲音

在遊戲操作區放獨立的「啟動無人機」按鈕，手機橫直向都能觸及。按鈕和啟動畫面共用一次啟動狀態，連點不重複建立機體或排入語音。以下是首次啟動的分鏡。

| 階段 | 畫面與真實狀態 | 音效與語音 |
| --- | --- | --- |
| 按下啟動 | 底色轉暗，收翼機械鳥的線框浮現。同時開始準備鳥身、起飛區域與鏡頭。 | 合成低頻脈衝，接一段短促的上升音。 |
| 光環喚醒 | Haloflux 式掃描弧停頓後加速，沿鳥胸和翼根亮起。核心完成初始化時點亮。 | 英文電子女聲 **“Core online.”** |
| 終端校準 | 掃描弧縮成鳥身檢查圖，550C 式等寬日誌分批進場。機體、左右翼、尾翼、起飛區地形與追尾鏡頭各自回報完成，對應的鳥身部位同步點亮。 | 左右翼各一個帶方向感的伺服聲，日誌仍可在靜音時完整傳達狀態。 |
| 飛行就緒 | 鳥身與首個可用飛行畫面、起飛淨空和操控確認就緒後，顯示 **FLIGHT READY**。 | 英文電子女聲 **“Ready for flight.”**，配短促雙音確認。 |
| 交接自由飛行 | 終端面板先退場。線框的頭向、翼尖和胸口亮點對正下一鏡的 3D 鳥體，再揭開峽灣追尾畫面，玩家可立即控制。 | 羽板展開的金屬滑動聲接到峽灣風聲，語音清楚收尾。 |

首次動畫的設計節奏約 2–3 秒，準備較慢時停在實際未完成的狀態。資源就緒後再次啟動，可縮成短掃描和最後一句語音。若啟動失敗，顯示卡住的項目並可重試或返回。聲效採程式合成，電子女聲輕度窄頻處理，確認音和環境音在人聲期間降低音量。聲音延遲或不可用時，日誌與飛行狀態仍照常交接。

啟動畫面可用 Canvas 2D 畫線框、掃描弧及低解析度輝光，終端狀態用少量 DOM 文字。手機版只顯示最近幾行與檢查圖，完整動畫與 3D 場景只在必要的揭幕區間短暫疊畫。粒子、音效與轉場的生命週期隨啟動結束或取消一併收束。

## 5. 品質驗收

| 項目 | 驗收內容與證據 |
| --- | --- |
| 造型與動作 | 固定正面、側面與後上方鏡頭，以順光和背光錄下展翼、收翼、側傾、俯衝與拉起。灰模也應看得出尖喙、窄身、分片主翼和扇尾。慢放確認無明顯羽板穿插及閃爍，追尾視角能讀懂翼面動作。 |
| 啟動與交接 | 錄下首次、再次和延遲載入，另測連點、取消、失敗及重試。逐幀比對終端末格與飛行首格的鳥頭朝向、翼尖、胸口亮點。從按鈕點擊到首個可操控畫面另行計時，與 2–3 秒的動畫節奏分開記錄。 |
| 聲畫 | 用手機喇叭與耳機各錄一段，兩句英文都能辨識，校準燈光對上伺服聲，確認音和展翼聲自然過渡到風聲。靜音模式仍可看懂所有狀態。 |
| 操控 | 固定 Hellesylt 航線，依序低空掠水、急轉、俯衝拉起。錄影核對輸入後首個可見反應、鏡頭穿地或抖動、地平線可讀性與手機橫直向觸控。 |
| 效能 | 在 POCO F8 Ultra 和實際可用的 iPhone 上記錄版本、後端、畫質與渲染比例。以 60 Hz、穩定 60 FPS 為 WebGPU 手機目標，測首次啟動、再次啟動與 20 分鐘飛行。記錄啟動與飛行的幀時間 p95、最慢幀、超過 50 ms 的幀、比例變化及長跑掉速。WebGL2 Lite 驗證同一套狀態、操控和簡化轉場可用。 |
| 成本對照 | 固定航線、天氣、鏡頭和畫質，依序比較場景基準、加鳥體、再加特效。飛行比較使用同一條鏡頭軌跡，即使隱藏鳥體也照樣播放。過高時優先減少粒子、輝光和殘影。 |
