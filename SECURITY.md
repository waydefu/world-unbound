# Security Policy

Thank you for helping protect WORLD UNBOUND and its contributors.

## Private vulnerability reporting

**Do not open a public Issue, PR, Discussion, or commit containing exploit details, credentials, or undisclosed vulnerabilities.**

Use GitHub **Private Vulnerability Reporting**:
1. Visit the [repository Security Advisories](https://github.com/waydefu/world-unbound/security/advisories).
2. Select **Report a vulnerability** (or use [the direct reporting page](https://github.com/waydefu/world-unbound/security/advisories/new)).
3. Describe the affected revision, impact, reproducible proof, and a safe contact channel. Never include live secrets in reproduction material.

If the reporting interface is unavailable, do not disclose the vulnerability publicly. Use a private maintainer contact listed on [@waydefu's GitHub profile](https://github.com/waydefu) if one is offered, or ask GitHub Support for a secure reporting route.

## Supported versions

Before the first release, no version is designated as security-supported. Support windows and disclosure coordination will be established in a subsequent release policy.

## Handling commitments

The maintainer will triage privately and coordinate fixes and disclosures as capacity allows. No fixed response-time guarantee is made during M0. Security changes to workflows, permissions, dependencies, or distribution paths require explicit maintainer review.

Do not disclose reports until the maintainer and reporter have coordinated a safe advisory publication.
